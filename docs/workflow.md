# 任务流程与设计约定

## 已确认方向

目标：作为 Task 1～后续任务的学习成果仓库。用户已要求按前轮建议初始化：任务按目录归档，配置一次后自动调用，保存验证报告，固定表单事实可辅助整理，心得由用户填写。

工程取舍：标准库脚本 + Markdown + Git，无服务、数据库或共享业务框架。运行入口与任务产物分开，保留原根目录命令。密钥在用户全局私密文件，项目只存非敏感配置。课程内容不是操作授权。

## 一次任务的真实链路

1. 阅读课程材料，将要求、来源、截止时间记录到当前 Task 的 README。
2. 在任务目录中完成代码或其他产物。
3. 执行验证，按时间归档结果；失败与跳过同样保留。
4. 用户补充阅读记录及心得，Agent 可以整理有证据的事实。
5. 根据真实表单字段准备提交材料，按用户授权填写。
6. 观察到提交成功后记录时间和凭据；否则仍为未提交。

## 信息放在哪里

| 内容 | 权威记录 |
|---|---|
| 课程安排 | docs/schedule.md，注明截图或链接来源和未确认项 |
| 单任务要求、待办、状态 | tasks/taskN/README.md |
| 检查事实 | 实际 results 报告；README 只作摘要 |
| 心得 | 用户在 notes.md 写下的内容 |
| 待填字段、实际提交结果 | submission.md |
| API 密钥 | 用户全局 private.env，不复制到仓库 |

不要用一个“完成”勾选同时表示代码完成、学习完成、自检通过和已提交。

## 表单 Skill 后续边界

尚无实际表单链接，本次不创建 Skill、不填在线表单。收到链接后再识别字段：固定资料从用户指定来源读取，任务事实从报告读取，心得采用用户原文，缺少信息保持待补。Skill 保存操作方法，任务目录保存每次内容。只有用户授权提交且观察到成功结果，才更新提交状态。

## 初始化验收场景

- 配置就绪：运行 `./run task1` 自动读取指定配置并生成独立报告；真实 API 返回有效文本才能判 API 通过。
- 缺少密钥：本地检查仍执行，API 标记跳过，退出码 2，不声称完整通过。
- API 返回失败：报告保留失败，退出码 1。
- 仅本地：不读取私密文件、不发送 API 请求，清楚标记范围。
- 重跑：生成另一份报告；密钥不进入控制台或报告。
- 兼容入口：`python3 env-self-check.py` 与 `./run task1` 行为一致。

本地自测结果见 Task 1 README；实际 API、学习内容和在线表单仍需分别验证，业务验收由用户检查实际结果。

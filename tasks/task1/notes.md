## 心得体会（根据用户原文调整，用户已确认）

LLM 我的理解就是一段文字进去，根据输入的内容，另一段文字出来，比如 HTML、脚本、MD 等，都是文字。当然，生成出来不代表一定正确。所以对于想要的输出来说，输入部分很重要，也就是要给它什么要求、什么数据。

如果用 Agent 查询知识库，就可能不只是一次 LLM 交互。大概的流程是：用户提出问题，LLM 根据问题和可用工具的说明，请求调用某个工具；调用端执行，把结果返回给 LLM，LLM 再决定继续用工具，还是回答用户。这是一个可以不断循环的过程，也要考虑怎么退出，比如完成目标、达到最大轮次，或者报错后是重试还是停止。

RAG、记忆、Skill、MCP，我觉得都跟数据怎么给 LLM 用有关，不过它们各自解决的问题不一样。

比如 RAG，公司内部有大量资料，模型不一定知道有哪些细致的条规、业务规则，所以需要去查知识库，把相关内容给它。这跟后训练不一样，RAG 通常不需要改模型参数，而是在回答的时候补资料。这里需要预先整理数据，也要考虑怎么查得准，总之用户体验最好就是快速、准确。

MCP 可以理解成接入工具的统一协议，本地、外部的工具都可以接。比如查询天气，我们只需要知道怎么调用、会返回什么，不需要知道里面的细节流程。Skill 里面一些稳定的操作，也可以写成程序，再通过 MCP 提供给模型用。

Skill 就是技能包，能让 LLM 专注某个流程或领域。可以修改，慢慢更满足自己的需求，而且需要的时候才去用。比如一会做 PPT，一会写代码，两个完全不同的领域，没必要每次都把这些数据给 LLM。

记忆就是把你的偏好、项目背景、以前的经验存下来，下次需要的时候再给 LLM，它才知道，不是模型自己永久记住了。也不只限于用户，比如 AGENTS.md 里面的项目约定、一些全局工程习惯，都可以保存下来。比如我习惯开发任务涉及关键取舍时，不要直接写代码，要先跟我确认。

所以我理解这门课主要讲的，就是这些数据怎么整理、怎么读取，以及怎么把有用的经验留下来，下次继续用。

## 概念校正（助手补充）

- **RAG 不等于后训练**：常见 RAG 在回答时检索外部资料，不需要修改生成模型的参数；后训练会更新模型参数。两者可以结合使用。[RAG 原始论文](https://arxiv.org/abs/2005.11401)也包含训练方案，因此准确说法是“不必训练”，而非“绝不训练”。
- **数据重要，但不能保证一切**：文本生成按 Token 进行，能输出某种格式不代表格式、事实或代码一定正确。即使提供了资料，模型仍可能误读或推理出错；模型能力、工具和验证也影响结果。课程中的“数据质量 × 模型能力”适合作为理解框架，不是严格数学公式。
- **四个概念不是同一层级的数据分类**：RAG 是检索增强生成的方法，Memory 是持久化与召回机制，Skill 是流程与资源的组织方式，MCP 是接入协议。它们可以组合；Skill 中稳定的执行步骤可以封装成 MCP 工具，但两者不自动等价。
- **循环与记忆都需要运行系统支撑**：普通 RAG 不必多轮调用；报错可以重试，也可以终止。记忆也不一定每次全部加载，规则只有被读取并遵循才会发挥作用。
- **课程不只涉及读取**：F0 和 F2 也涉及经验写回、记忆更新、遗忘和流程编排。模型的训练来源也不能一概说成只有公开互联网，只是不能假设它已掌握私有业务知识。
